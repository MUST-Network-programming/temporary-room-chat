## 录屏操作（全部使用测试身份，不填真实邮箱）

1. 打开 8090，以“房主”创建房间。在房间信息中更改群名，比如“周末出行”。复制房间码。
2. 用独立标签页 / 窗口，以“游客”加入（标签页会话独立）。点击“行程与提醒”，填 `traveler@example.test` 并订阅。
3. 在游客群聊发送以下内容，日期用明天。规则演示只识别明确标签，普通随意措辞不擅自猜测：

```text
日期：明天；集合时间：08:30；集合地点：酒店大堂；目的地：城市博物馆；交通：旅游巴士；停留时长：90分钟；游览结束集合时间：11:20；再次集合地点：景点东门旅游巴士停车区；车辆座位数：45；注意事项：携带身份证和饮用水；行程安排：08:45乘车，09:30游览
```

4. 房主在群聊发送 `@行程助手 生成明日行程草稿`。草稿打开，顶部明确写“规则提取 / 本地演示（非 AI）”。缺失或冲突显示“待确认”。
5. 房主将集合地点改成“酒店一楼大堂”，勾选“一分钟后本地测试提醒”，确认发布。群里出现真实的房主确认行程消息（文案为「已确认行程 vN」）。上方置顶条只显示当前版本；若群里还有旧确认卡片，会被标记为「历史版本」，不会改写服务器里已保存的原文。
6. 查看排期；等待一分钟，打开 8025，看**实际 SMTP 接收的 MIME 邮件**，并查看群内“已发送 / SMTP 已接受”记录。不是伪造收件截图。
7. 如需展示改期取消：在一分钟到期前，修改已确认时间 → **先保存新草稿** → 再勾选一分钟演示 → 确认新版。旧版 pending 全部取消，新版重排；最终只有新版演示邮件收到。取消订阅会取消本人未来提醒。
8. 游客只能查看已确认版和本人订阅，不能生成 / 编辑 / 确认；后端也会拒绝，不能靠改前端按钮绕过。

## 已实现与配置边界

- C 负责账号、房间、WS/WSS、成员身份。后台每次 HTTP 操作通过共享密钥 RPC 查询 C 的**真实有效成员令牌**；不接受前端指定任意成员或房主标记。
- SQLite 持久化草稿、确认版、订阅、任务、投递日志。已确认行程编辑为新草稿，新版确认后才替换置顶并取消旧提醒。
- 固定标准提醒：前一晚20:00、集合前30分钟，时区 `Asia/Shanghai / UTC+8`；过去的标准时点不补发。一分钟演示仅本地投递模式可用，需先订阅再确认。
- 确认必填：日期、集合时间、集合地点、目的地。导游停留 / 再次集合 / 座位数等是信息字段，未提供仍为待确认，不声称具备任何未经核实的合规资质。
- 真实 AI 接口就绪：OpenAI-compatible Chat Completions，环境变量 `AI_MODE=openai`、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`。本次没有配置或调用真实 AI；失败不伪装为 AI 成功，也不静默规则兜底。
- 真实 SMTP adapter 支持 STARTTLS / SSL 和环境变量认证；本次仅发送到本机 SMTP。没有真实外部邮件、Gmail 凭证或连接器。
- 默认拒绝非 `@example.test` 收件人，SMTP capture 也独立拒绝其他地址。真实域名投递必须明确开启 `ALLOW_EXTERNAL_EMAIL=1` 并配置供应商。
- 邮件中群聊链接使用 `PUBLIC_BASE_URL`，非硬编码 localhost。
- 待发送任务可在 API / worker 重启后恢复。`sending` 崩溃窗口一律变为 `uncertain`，**不自动重发**，避免重复；SMTP“接受”不等于保证外网最终送达。SMTP 在协议层不能承诺跨崩溃严格 exactly-once，不能把不确定状态伪报成功。
- 内部成员验证暂时不可用时保留 pending 重试；确认无成员、房间或版本时才取消。
- C 房间本身沿用原项目的内存生命周期，C 重启后房间消失；此时成员验证失效，旧邮件会取消，不会替旧房间发送。不是线上数据迁移方案。
- 演示由浏览器收到自己发送的 @ 消息后调用受鉴权提取 API；其他自制 WS 客户端需主动调用同一 API。本次不包含通用机器人回复、任意自然语言智能对话或退信/投诉 Webhook。

## 部署前说明（文档示例，不是本次部署）

- 线上需保留 C 原有账户模式（注册码、TLS、账号数据库），不要将 `--anonymous-loopback` 当公网认证。
- 共享密钥随机生成、至少32字符，同时提供给 C 和后台；禁止前端包含、提交或写日志。数据库保存订阅邮箱与成员能力令牌，应放私有目录、0700目录/0600文件、最小授权和备份。
- 真实 AI 和 SMTP 密钥全部环境变量，源码包不含 `.env`、运行时DB、证书私钥或收件内容。
- HTTPS/WSS 反向代理可以将 `/ws` 转给已启用 TLS 的 C（或 gateway），`/api/itinerary/` 转给 loopback 8090，静态文件同源提供。必须保留 WebSocket Upgrade 和足够长的读超时；API 的 AI 调用超时应大于45秒。
- C 不允许匿名监听公网；原程序账户模式要求证书，即使在 nginx 后也保持其启动校验，配置 CA 验证的内部 `wss://`。
- `serve`、`worker` 分别由 systemd 等守护；只启动一个 worker。SMTP capture 只供本机开发，不能公开8025/1025。
- URL 中 `43.129.182.26` 是 IP。若以后绑定真实域名，替换 `PUBLIC_BASE_URL`，同步 HTTPS 证书及反向代理配置。本轮没有访问或写入该线上地址。
