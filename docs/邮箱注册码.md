# 邮箱注册码

## 策略

邮箱能收到信，只说明对方控制这个邮箱，不等于原来的邀请授权。

默认不变：

- `REGISTRATION_EMAIL` 不是 `1` 时，注册页隐藏邮箱发码入口，网关停止发放邮箱注册码。此时网页注册使用组织者用 `chat_server --accounts … --issue-invite` 在本机生成的注册码。
- 该命令仍把注册码打印给组织者。这条路径不发信。
- 已有账号库、组织者已发出的注册码、匿名回环演示都继续可用。关闭后，服务端仍按原有效期校验此前发出的邮箱注册码。
- 生产不要改成匿名模式，浏览器账号注册和登录仍必须走 HTTPS/WSS。

显式打开 `REGISTRATION_EMAIL=1` 之后，多一条邮箱注册：

- 访客在注册页填写邮箱并请求注册码。服务端生成一次性随机码，只放进邮件正文，不放进网页响应，也不写入普通日志。
- 这时，**能收到该邮件即被允许注册**。这是管理员主动放宽授权，不是默认行为。
- 组织者本地 `--issue-invite` 仍然有效，两种码可以同时存在。
- 邮件注册码绑定规范化后的邮箱（全部小写），约 10 分钟过期，只能使用一次。邮箱不匹配会累计次数，满 5 次后作废。同一邮箱 60 秒内不能重发；过期重发会使上一封未使用的码失效。同一 IP、同一邮箱在时间窗内有次数上限。
- 已经用该邮箱注册过的地址，再次请求不会再发信。接口仍返回和“已受理”相同的结果，避免用这个接口探测账号是否存在。SMTP 失败不是这种结果：失败会删除刚生成的码，并返回“没有生成可用注册码”，不会假装成功。
- `ALLOW_EXTERNAL_EMAIL` 仍然生效。默认 `0` 时只允许本机 SMTP，且收件人必须是 `@example.test`。这不能变成开放中继，也不能绕过行程邮件的外部发送开关。
- 注册码邮件不走行程提醒的定时任务，失败不自动重发。

本地 `scripts/preview-v2.sh` 会把 `REGISTRATION_EMAIL` 固定为 `0`。捕获用的 8025 收件箱只给本机测试，不能公开。

## 启用真实 SMTP 前的配置清单

1. 备份账号库、证书和私钥，放在网站目录之外。C 进程重启会丢掉内存里的房间和聊天记录，不能当成无感操作。
2. C 账号模式继续使用原来的证书和 `--accounts` 指向的同一个数据库。不要加 `--anonymous-loopback`。
3. Python 网关和 C 使用同一份 `ACCOUNTS_DB`（绝对路径）。只开 C、不开启网关时，邮箱请求会失败，本地邀请码注册仍可用。
4. 网关只监听本机。公网入口对 `/api/register/code` 使用 `proxy_set_header X-Real-IP $remote_addr;` 覆盖同名请求头。API 仅接受本机代理传入的有效单个 IP，缺失或无效时统一按本机地址限流。对外保持 HTTPS。`/api/register/policy` 和 `/api/register/code` 与页面同源；WebSocket 仍由网关转到 C 的 WSS，不要改成明文 ws。
5. 在网关环境中设置 `REGISTRATION_EMAIL=1`、`SMTP_HOST`、`SMTP_PORT`、`SMTP_FROM`。需要认证时再设置 `SMTP_USERNAME` 和 `SMTP_PASSWORD`，只放环境变量，不写入仓库。465 端口设 `SMTP_SSL=1`；其他外部 SMTP 使用 STARTTLS。
6. 确认要向真实邮箱发信后，才把 `ALLOW_EXTERNAL_EMAIL` 设为 `1`。在此之前，非 `@example.test` 地址会被拒绝。
7. 行程提醒、注册码、通知邮箱验证码和重要通知共用上述 SMTP 开关。注册邮箱须由成员主动绑定后才接收重要通知。不要公开本地收件箱。
8. 真实发信是否成功，要在配置好 SMTP 后单独验证。仓库和测试都不包含真实邮箱凭据。

## 部署时要同时有的进程

- `chat_server`：账号模式、TLS、原账号库。负责校验注册码、创建账号、HTTPS/WSS。
- `assistant/service.py serve`：本机网关，提供注册码接口，并把浏览器 WebSocket 转到 C。
- 真实 SMTP。`capture` 只用于本机测试，不要在生产启动，也不要映射 8025 或 1025。
