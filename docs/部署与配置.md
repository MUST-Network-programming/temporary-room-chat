# 部署与配置

本文说明在本机、局域网与已有云实例上运行同行。基础聊天的安装入口见[README](../README.md#快速开始)。

## HTTPS 与账号模式

### 本地证书

在项目根目录运行，需要 `openssl` 命令：

```sh
python3 tls/make_certs.py
```

脚本生成 `tls/certs/ca.crt`、`server.crt` 及对应私钥。已有 CA 时会拒绝覆盖；不要反复重新生成已受信任的 CA。需要在实际访问设备上信任演示 CA，证书的 SAN 必须包含访问地址。

局域网访问时，生成前指定服务器的真实 IP：

```sh
python3 tls/make_certs.py --ip 192.168.1.20
```

`192.168.1.20` 为示例地址，请替换为服务器的实际网卡地址。公网部署使用与访问地址匹配、由受信任 CA 签发的证书。演示 CA 和服务器私钥保留在服务器上，客户端只需信任 CA 证书。

### 启动账号模式

启动 C 聊天服务，使用现有账号库或指定一个新路径。

```sh
./build/chat_server --bind 0.0.0.0 --port 8443 \
  --accounts accounts.sqlite3 \
  --cert tls/certs/server.crt --key tls/certs/server.key
```

浏览器通过 HTTPS 网关打开，网关通过 WSS 转发聊天连接，并提供验证码接口。将网关的 `ACCOUNTS_DB` 设为同一账号库。成员验证邮箱后登录，房间身份来自账号。

### 数据保存

账号和登录验证状态保存在账号库。房间库默认在账号库路径后追加 `.rooms.sqlite3`，可通过 `--rooms-db FILE` 或 `CHAT_ROOMS_DB` 指定其他路径，命令行参数优先。

房间、成员和聊天记录保留到房间到期或被房主关闭，默认有效期为 7 天。可用 `--ttl` 缩短有效期进行验证，范围为 1–604800 秒。一个房间库由一个 C 聊天进程使用。

浏览器按访问地址保存最近 5 个房间，HTTP、HTTPS 与不同地址各自拥有独立列表。登录与房间令牌保存在当前标签页的 `sessionStorage`。服务重启后重新登录，可回到仍有效的持久化房间。

## 群聊助手、行程与邮件

在已完成 C 构建的目录中安装 Python 依赖：

```sh
python3 -m venv .venv
.venv/bin/pip install -r assistant/requirements-lock.txt
```

Ubuntu 未安装 `venv` 时先安装 `python3-venv`。配置项以[`.env.example`](../.env.example)为准；生产环境将实际值放入服务进程的环境变量或私有配置文件。

| 配置 | 用途 |
| --- | --- |
| `ASSISTANT_SHARED_SECRET` | C 与任务服务之间的共享认证密钥，至少 32 个字符。 |
| `CHAT_INTERNAL_WS` / `CHAT_CA_FILE` | 内部聊天连接地址及受信任的 CA；WSS 验证证书与主机名。 |
| `ACCOUNTS_DB` | 与 C 服务相同的账号数据库。 |
| `ASSISTANT_STATE` | 行程、通知、订阅和任务状态目录。 |
| `PUBLIC_BASE_URL` | 邮件中指向聊天站点的公开地址。 |
| `AI_MODE` | `rules` 使用本地演示；`openai` 使用配置的模型接口。 |
| `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY` | 兼容 Chat Completions 的模型接口配置。 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_FROM` | 邮件服务器与发件地址。 |
| `SMTP_USERNAME` / `SMTP_PASSWORD` | 邮件认证凭据。 |
| `SMTP_SSL` | `1` 使用隐式 TLS；外部非隐式 TLS 的 SMTP 要求 STARTTLS。 |
| `ALLOW_EXTERNAL_EMAIL` | 默认 `0`，只投递到本地测试收件箱；真实投递需设为 `1`。 |
| `LOGIN_CODE_TTL` / `LOGIN_RESEND_SECONDS` | 验证码有效期和重发间隔，默认分别为 300 秒和 60 秒。 |

### 本地完整预览

```sh
PUBLIC_BASE_URL=http://127.0.0.1:8090 ./scripts/preview-v2.sh
```

打开 `http://127.0.0.1:8090` 聊天，在 `http://127.0.0.1:8025` 查看本地 SMTP 收件箱。使用 `traveler@example.test` 等测试邮箱。脚本固定使用规则提取、演示回复和本地邮件，不调用真实模型或外部邮箱。

账号模式预览需要已生成且受信任的本地证书：

```sh
PUBLIC_BASE_URL=https://127.0.0.1:8090 ./scripts/preview-v2.sh --accounts
```

访问 `https://127.0.0.1:8090`，输入测试邮箱并点击「发送验证码」。到 `http://127.0.0.1:8025` 查看验证码。登录后可在大厅绑定通知邮箱。

### 真实部署

完整服务包含 C 聊天进程，以及 Python 的 `serve`、单个 `worker`。`capture` 仅用于本地测试邮件。生产网关将 WebSocket 与 API 接到同源入口，示例见 [Nginx 配置](nginx-v2.conf.example)。

- 真实 AI 需要切换到 `AI_MODE=openai` 并配置接口凭据，演示回复不会被标成真实 AI 输出。
- `@群聊助手` 回答问题；`@行程助手` 提取草稿，草稿由房主编辑确认后发布。
- 重要通知支持预览接收覆盖人数和按北京时间排期；已发布通知在房间关闭或到期后仍按其任务状态处理。参与者可解绑邮箱，房主可改期或撤销未发送任务。
- 保留账号、房间库与 `ASSISTANT_STATE`，C、API 与 worker 使用一致的认证与邮件配置。只运行一个 worker。
- 本地 SMTP 收件箱端口 `8025` / `1025` 仅绑定 loopback，不作为公网服务。

## 当前云实例升级

[`scripts/upgrade-cloud.sh`](../scripts/upgrade-cloud.sh)面向项目现有 Ubuntu/systemd 部署，其账号库与服务名已有约定，不能直接作为任意服务器的安装脚本。

将对应版本的源码部署包上传到 `/home/ubuntu/`，解压并进入该版本目录，再运行：

```sh
sudo bash scripts/upgrade-cloud.sh
```

脚本检查 `REVISION` 和当前部署，先编译和测试，再备份数据库与配置、切换服务，检查 HTTPS/WSS、邮箱登录策略和前端资源。失败时尝试恢复旧版服务；现有 Gmail 配置覆盖文件会保留。重启会断开连接，重新登录后可加入尚未到期的持久化房间。

## Windows 原生构建

安装 Visual Studio 2022 Build Tools（C++ 桌面开发工作负载、Windows SDK 和 CMake）、Git 与 Python 3。在 Developer PowerShell for VS 2022 中运行：

```powershell
git clone https://github.com/microsoft/vcpkg.git C:\vcpkg
C:\vcpkg\bootstrap-vcpkg.bat
C:\vcpkg\vcpkg.exe install openssl:x64-windows sqlite3:x64-windows
cd '项目所在路径\temporary-room-chat'
cmake -S . -B build-win -G 'Visual Studio 17 2022' -A x64 -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows
cmake --build build-win --config Release
$env:PATH = 'C:\vcpkg\installed\x64-windows\bin;C:\vcpkg\installed\x64-windows\tools\openssl;' + $env:PATH
.\build-win\Release\chat_server.exe --anonymous-loopback --port 8080
```

打开 `http://localhost:8080`。账号模式同样需要 `--accounts`、`--cert` 和 `--key`。源码包含原生 MSVC/Winsock 路径，上述 Windows 流程仍需在实际 Windows 环境验证。

## 服务端日志与验证

启动 C 服务时加入 `--log-chat`，会向标准错误输出房间事件和聊天正文，适合维护者排查问题；默认关闭。

```sh
ctest --test-dir build --output-on-failure
python3 tests/integration.py
python3 tests/integration.py build/chat_server tls/certs
python3 tests/accounts.py
python3 tests/room_persistence.py
```

TLS 集成验证需要上述证书文件。协议和权限细节见[协议与设计说明](协议与答辩.md)，登录与迁移步骤见[邮箱验证码登录](邮箱登录.md)。
