# 协议与答辩

## 总体数据路径

浏览器 WebSocket → Socket/TLS 连接 → WebSocket 帧解析 → JSON 业务校验 → 房间管理 → 输出队列 → WebSocket/TLS → 浏览器。

所有 socket 状态在一个 select 事件循环中修改，避免多个线程同时操作房间造成数据竞争。房间和会话只存在内存中。

## 消息示例

创建与加入。

```json
{"type":"create","nickname":"小陶"}
{"type":"join","room":"ABC234","nickname":"小李"}
{"type":"join","room":"ABC234","nickname":"小李","token":"服务器上次签发的令牌"}
```

聊天与管理。

```json
{"type":"chat","text":"十点在门口集合"}
{"type":"ping"}
{"type":"leave"}
{"type":"close"}
```

加入成功返回 joined，携带 room、nickname、token、owner、expires。成员更新返回 members 数组，聊天返回 nickname/text。错误返回 error 与 code/message，关闭返回 closed 与 reason，心跳返回 pong。

业务只接受规定字段。类型错误、重复键、未知字段、NUL、非法 UTF-8、超长消息均拒绝。WebSocket 层先验证帧，完整消息再进入业务层。消息上限 8192 字节，正文上限 2048 字节，昵称上限 48 字节。

## 关键边界

- TCP 只提供有序字节流，recv 次数与消息数量没有一一对应关系。
- WebSocket 把字节流分成帧，一条消息仍可能由多个帧组成，控制帧可穿插其间。
- room_message 收到完整 UTF-8 文本后才解析 JSON，业务模块无需直接读 socket。
- 每房间最多 64 个会话，全局最多 256 个会话。离线会话保留到过期，因此占用名额；显式退出会撤销会话。
- 昵称是显示信息，令牌才用于恢复身份。同名匿名加入会拒绝。
- 房间关闭或到期后撤销所有会话。房主网络断开保留恢复机会，显式离开则关闭房间。
- 输出队列上限 512 KiB，慢客户端队列满时断开，其他成员继续通信。
- TLS 使用成熟 OpenSSL 库；WebSocket 与房间协议由项目的 C 代码实现。

## 十五分钟汇报安排

| 顺序 | 时间 | 重点 |
| --- | --- | --- |
| server | 0～3 分钟 | 场景、select、非阻塞、多连接与退出清理 |
| websocket | 3～6 分钟 | HTTP 升级、帧、分段组装和非法输入 |
| rooms | 6～9 分钟 | 房间隔离、在线列表、权限、关闭和过期 |
| web | 9～12 分钟 | 浏览器流程、心跳、重连与恢复身份 |
| tls | 12～15 分钟 | TLS、证书验证、明文与加密抓包 |
