# tls · TLS 安全通信

`tls.c` 提供连接层统一收发接口。普通模式调用 recv/send，TLS 模式调用 SSL_read/SSL_write。服务端最低允许 TLS 1.2。证书和私钥由启动参数传入。

## 非阻塞状态机

SSL_accept、SSL_read、SSL_write 都可能要求等待 READ 或 WRITE。这个方向与函数名字不一定相同。调用 SSL_get_error 后将方向记录在 Client 中，由 select 监听对应事件再重试。所有 OpenSSL IO 前清空当前线程错误队列。

SSL_write 重试的地址、长度、内容必须相同，发送队列在待发送期间保持稳定。连接清理尝试发送 close_notify，随后释放 SSL 对象和 socket；等待对端关闭不会阻塞所有用户。

## 依赖与证书

macOS 使用 `brew install openssl@3`，CMake 的 OPENSSL_ROOT_DIR 指向 `brew --prefix openssl@3`。

Windows 使用 README 的 vcpkg x64-windows 安装并通过 CMake toolchain 链接，运行时把 bin 与 tools/openssl 加到 PATH。

```sh
python3 tls/make_certs.py
./build/chat_server --port 8443 --cert tls/certs/server.crt --key tls/certs/server.key
```

CA 有效期 30 天，服务端证书 7 天。SAN 默认包含 localhost 和 127.0.0.1，可用 --ip 参数加入实际局域网地址。密钥由本机 OpenSSL 生成。

macOS 用“钥匙串访问”导入 ca.crt 到登录钥匙串，打开证书的信任设置并设为始终信任。浏览器重启后访问 https://localhost:8443。只在演示期间信任该 CA，演示完从钥匙串移除。

Windows 双击 ca.crt，选择安装证书、当前用户、受信任的根证书颁发机构。重启 Edge/Chrome 后访问匹配证书 SAN 的地址。演示结束运行 certmgr.msc 找到 Temporary Chat Demo CA 并移除。Firefox 若使用独立证书库，应在浏览器证书设置中导入该 CA。

## 自动身份验证

```sh
python3 tests/integration.py build/chat_server tls/certs
```

Python SSL 客户端使用指定 CA，验证可信证书成功、系统未信任该 CA 时拒绝、错误主机名拒绝。这与浏览器手工导入信任是两项验收，浏览器的手工信任演示须单独记录。

## 抓包对比和三分钟演示

1. 先在 HTTP/WS 模式发一个唯一正文 `PACKET_DEMO_2026`，Wireshark 本机选 lo0（Windows 选 Npcap Loopback Adapter），局域网选实际网卡，过滤 `tcp.port == 8080`。Follow TCP Stream 可查看 WebSocket 帧，客户端掩码可逆，服务端正文为明文。
2. 切换 HTTPS/WSS 模式，过滤 `tcp.port == 8443`，发送同一正文。Follow TCP Stream 显示 TLS 加密记录。保持浏览器 TLS 密钥日志未导出。
3. 展示受信任证书正常访问，再用 SAN 未包含的地址或未导入 CA 的浏览器展示证书错误。拒绝继续访问错误证书页面。
4. 解释 TLS 加密范围为浏览器到服务器，房间码与房主令牌属于应用层权限。
