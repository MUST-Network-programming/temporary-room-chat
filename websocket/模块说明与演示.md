# websocket：WebSocket 与业务协议

## 模块边界

`websocket.c` 将 TCP/TLS 提供的字节流还原成完整的 UTF-8 文本消息。连接层把新字节追加到 `Client.input`，调用 `ws_process`；收到完整消息后，本模块调用 `room_message(client, text, length)`。消息不保证以 `\0` 结尾，业务层必须使用传入长度。

`ws_handshake` 只处理完整 HTTP 首部。HTTP 层必须先找到 `\r\n\r\n`，提供以 NUL 结尾的首部文本，调用后移除首部字节，再把剩余字节交给 `ws_process`。握手返回 1 表示成功，返回 0 表示失败且已入队 400 响应。失败时 `closing=1`，连接层发送完队列后断开。

## 从字节到消息

1. 至少收到两字节才能知道 FIN、opcode、掩码位和初始长度。
2. 长度为 126/127 时，再等待扩展长度字段；拒绝非最短长度编码。
3. 检查客户端必须带掩码、RSV 必须为零、总长度不能超过 8192 字节，然后等待剩余掩码和负载。
4. 负载每字节与四字节掩码循环异或，恢复原始数据。
5. 普通文本帧与续帧追加到 `message`。FIN=1 才进行完整 UTF-8 校验并交给房间模块。一个汉字可以跨帧传输。
6. 控制帧可插在分片之间；ping 立即回复相同负载的 pong。已消费的输入从缓冲区移除，尚未完整的字节保留至下次读取。

服务器帧设置 FIN=1、不使用掩码。`queue_bytes` 负责排队，实际发送和部分写入由server完成。

## 握手与支持范围

请求必须为 `GET /ws HTTP/1.1`，包含 Host、Upgrade、Connection、版本 13 和合法的 16 字节 Base64 key。首部名称及 Upgrade/Connection token 大小写不敏感。拒绝重复关键首部、折叠首部、非法名称及控制字符，以及请求体相关首部。

握手接受值为 `Base64(SHA1(key + GUID))`；SHA-1 用于 RFC 6455 固定握手算法，不用于密码或消息加密。浏览器可能发送扩展提议，但服务器不协商扩展，所以后续 RSV 位必须为零。

仅支持文本业务消息；不支持二进制消息、压缩、子协议。文本完整消息最多 8192 字节；房间层进一步限制昵称 48 字节、聊天正文 2048 字节。控制帧不得分片且不超过 125 字节。

关闭状态：1002 协议错误、1003 不支持的二进制、1007 非法 UTF-8、1009 消息过长。收到合法 close 时回送其负载并关闭。业务错误使用 JSON `error`，并不必然断开连接。

## JSON 协议

使用随项目提供的 cJSON。`send_json` 发送后自动释放传入的 JSON 对象，调用者不得再次释放。

| 客户端 type | 字段 | 说明 |
| --- | --- | --- |
| create | nickname | 创建房间 |
| join | room, nickname, token（恢复时） | 加入或恢复会话 |
| chat | text | 向当前房间发送 |
| leave | 无 | 主动退出并撤销会话 |
| close | 无 | 房主关闭房间 |
| ping | 无 | 应用层心跳 |

服务器返回 joined、members、chat、closed、pong、error；JSON 字段是否合法以及操作权限由rooms的房间模块统一校验。WebSocket ping/pong 与 JSON ping/pong 是两个不同层次。

## 实测与复现

2026-11-04，macOS 本机使用 clang 与 OpenSSL 3.6.4 编译，通过 `-Wall -Wextra -Wpedantic` 和独立单元测试。

在项目根目录执行：

```sh
sh websocket/测试.sh
WS_TEST_CFLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer' sh websocket/测试.sh
```

测试检查 RFC 示例握手 accept、缺少首部、单帧分多次读取、UTF-8 汉字跨帧、分片中插入 ping、非法 UTF-8、无起始帧的续帧、未掩码帧、正常 close、非法关闭状态、控制帧分片、二进制帧与超限长度。测试中用桩函数替代连接层和房间层，验证真实 WebSocket 实现。

Windows 原生构建与跨平台浏览器互通由总项目运行说明统一列出，当前本模块未在 Windows 实测。
